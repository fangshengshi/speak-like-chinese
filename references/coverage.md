## 统计（v1.5 起统一为 humanizer-zh 原 24 项口径）

按 humanizer-zh 原表 24 项逐行点算（不做合并）：

- **完整覆盖**：8 项 — #3、#7、#9、#17、#18、**#19、#21**、#22
- **部分覆盖**：6 项 — #1、#4、#5、#10、#23、#24
- **未覆盖**：9 项 — #2、#6、#8、#11、#12、#13、#14、#15、#20
- **不适用中文**：1 项 — #16（humanizer-zh 自己也注明此模式中文不适用）

合计 24 项 = 8 + 6 + 9 + 1。

### 实现项数（去重后）

speak-like-chinese 把 humanizer-zh 的 #19「协作交流痕迹」和 #21「谄媚语气」合并到一个 `sycophancy` 类别。所以**实现项数**为 7（不是 8）：

- 完整覆盖 8 项原始模式 → 7 个实现（去掉 #19/#21 合并产生的 1 个重复）
- 部分覆盖 6 项原始模式 → 6 个实现
- 未覆盖 + 不适用 共 10 项原始模式 → 0 个实现

### 三处文档统一口径

`README.md`、`SKILL.md` 和本文件 `coverage.md` 一律使用「8 / 6 / 9 / 1」（humanizer-zh 原 24 项），合并实现说明仅在本文件解释。覆盖率公式：完整 + 部分 = 14 项 / 24 项 ≈ 58%。

## speak-like-chinese 独有（humanizer-zh 没有）的能力

1. **互联网黑话词库**（赋能 / 抓手 / 闭环 / 颗粒度 / 底层逻辑 / 对齐 / 拉齐 / 落地 / 沉淀 / 组合拳 / 深耕 / 打通 / 心智 / 势能 / 锚定 / 高质量发展 等 50+ 词）——humanizer-zh 完全没有
2. **学术八股词库**（具有重要意义系列 / 研究表明 / 综上所述等中文论文模板）——humanizer-zh 完全没有
3. **英文翻译腔类别**（`ai_translation_artifact`：织锦 / 格局 / 不可磨灭 / 深深植根于）——独立分类
4. **专业语境豁免**（`context_safe_when` 字段）——humanizer-zh 没有这个机制，speak-like-chinese 给至少 30 个高敏感词加了术语豁免
5. **12 场景适配**——humanizer-zh 没有；speak-like-chinese 覆盖学术 / 公众号 / 知乎 / 小红书 / 微博 / 文艺 / 公文 / 法律 / 医疗 / 商业 PR / 教育课件 / 技术工件
6. **否定排比同段密度判断**——humanizer-zh 是无差别检测，speak-like-chinese 用同段 ≥2 处规则避免误删合法递进
7. **占位符反幻觉红线**——humanizer-zh 没有这个概念；speak-like-chinese 强制 `[TODO: 补X]` 必须保留为字面字符串
8. **结构性 AI 写作惯例**（编号回引 / 英文术语裸用 / 工时估算模板 / changelog 风格）——humanizer-zh 完全没有
9. **6 条强制护栏**（受规约文本 / 专业豁免 / 占位符 / 反向特征确认 / 评分非目标 / 模型自审）——humanizer-zh 没有显式护栏机制
10. **静态扫描器**（scan.py）——humanizer-zh 只有规则文档，speak-like-chinese 提供可执行扫描

## 何时该用哪个

- **如果你的文本主要问题是**「夸大象征意义 / 媒体报道堆砌 / 系动词回避 / 同义词循环 / 虚假范围 / 粗体内联标题列表 / 知识截止日期免责」 → **用 humanizer-zh**（speak-like-chinese 这些没覆盖）
- **如果你的文本主要问题是**「互联网黑话 / 学术八股 / 英文翻译腔 / 中文 AI 模板化 / 跨场景适配 / 反幻觉」 → **用 speak-like-chinese**
- **如果两类问题都有** → 可串行使用；任何串行流程里，speak-like-chinese 的反幻觉护栏优先级最高。若前一步引入未证实细节，必须回退，不得继续润色。

未来 v2.0 计划补全 humanizer-zh 未覆盖的 8 个模式中适合中文的部分。
